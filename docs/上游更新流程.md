# MarkText 上游更新流程

## 背景

`D:\Code\ArkTs\MarkText\vendor\marktext` 是上游 marktext 的 **git submodule**（URL 指向
`https://github.com/marktext/marktext.git`）。鸿蒙移植补丁保存在 submodule 内的分支
`port/harmony`，该分支已推到共享仓库 `https://github.com/1440196924/MarkText-HM.git`
（与主仓库同一个仓库），供协作者拉取。

```
D:\Code\ArkTs\MarkText\
├─ vendor\marktext\        ← git submodule（上游仓库）
│   ├─ origin             → https://github.com/marktext/marktext.git（上游）
│   ├─ local              → D:\Code\OpenSource\marktext（本机原始克隆，移植补丁唯一来源）
│   └─ shared             → https://github.com/1440196924/MarkText-HM.git（共享，port/harmony 已推送）
└─ scripts\port\build.ps1 ← 一键构建脚本
```

## 首次 clone 本仓库后的初始化

```bash
# 1) 拉取 submodule（上游 develop）
git submodule update --init vendor/marktext

# 2) 引入共享的移植分支（port/harmony 不在上游，需从共享仓库取）
git -C vendor/marktext remote add shared https://github.com/1440196924/MarkText-HM.git
git -C vendor/marktext fetch shared port/harmony
git -C vendor/marktext checkout port/harmony

# 3) （可选）本机已有原始克隆时，加 local remote 以便更新补丁本身
git -C vendor/marktext remote add local D:\Code\OpenSource\marktext

# 4) 安装依赖
cd vendor/marktext
pnpm install --ignore-scripts
pnpm run minify-locales
```

## 更新步骤（上游有更新时）

```bash
# 1) 更新 submodule 引用的上游
git -C vendor/marktext fetch origin
git -C vendor/marktext rebase origin/develop      # 把移植补丁垫到最新上游之上

# 2) 有冲突时：解决后
git -C vendor/marktext add <冲突文件>
git -C vendor/marktext rebase --continue
# 放弃: git -C vendor/marktext rebase --abort
```

rebase 结束后 submodule 的 HEAD 会领先 gitlink，需提交到主仓库：

```bash
git add vendor/marktext .gitmodules
git commit -m "chore: bump vendor/marktext"
git push origin master            # 推主仓库
git -C vendor/marktext push shared port/harmony   # 推共享移植分支（协作者能拉）
```

## 一键重新打包

```bash
powershell -ExecutionPolicy Bypass -File scripts\port\build.ps1
```

脚本依次执行：`minify-locales` → `pnpm --filter marktext build` →
esbuild 打包 main.js → `patch-main.js` 路径补丁 → robocopy 同步 renderer/静态资源
到 `web_engine/.../resfile/resources/app`。之后 `build_project` + `start_app` 部署。

## 协作（其他人操作）

协作者 clone 主仓库后：

```bash
git clone https://github.com/1440196924/MarkText-HM.git
git submodule update --init vendor/marktext        # 拉 submodule（上游 develop）
# 按「首次初始化」第 2 步取 port/harmony 分支
```

- 其他人更新上游：`git -C vendor/marktext fetch origin && git rebase origin/develop`，
  但**不要** push 到 `shared`（推送权限由你控制）；本地 rebase 后自测即可。
- 你收到别人的改动诉求时，统一由你在本机 merge/rebase 后推 `shared`。

## 移植补丁内容（port/harmony 分支）

补丁以 git 提交形式承载，`port/harmony` 相对上游 `develop` 只有 2 个提交：

1. `port: HarmonyOS adaptations (...)` — 基础适配：窗口控制按钮、碰一碰传图、
   文件关联、设置窗口关闭行为。
2. `fix: HarmonyOS runtime fixes (...)` — 运行时修复：保存 EPERM（跳过原子写
   临时文件）、窗口置顶（转发到 ArkTS）、帮助菜单项调整、关于页版本信息。

上游更新后 `git rebase origin/develop` 会把这两个补丁重新应用到新版上游之上。

## 移植补丁涉及的文件（rebase 冲突高发区）

以下文件是本工程对上游的改动，上游若更新这些文件大概率产生冲突：

- `packages/desktop/src/main/app/index.ts`（文件关联打开、knock confirm）
- `packages/desktop/src/main/app/windowManager.ts`（窗口置顶转发）
- `packages/desktop/src/main/filesystem/index.ts`（鸿蒙跳过原子保存）
- `packages/desktop/src/main/windows/editor.ts`（窗口尺寸、URL 解码、knock 转发）
- `packages/desktop/src/main/windows/setting.ts`（关闭行为）
- `packages/desktop/src/main/ipc/window.ts`、`bootInfo.ts`
- `packages/desktop/src/main/menu/templates/help.ts`（帮助菜单项）
- `packages/desktop/src/renderer/src/components/about/index.vue`（版本/移植者）
- `packages/desktop/src/renderer/src/components/titleBar/index.vue`
- `packages/desktop/src/renderer/src/prefComponents/common/titlebar.vue`
- `packages/desktop/src/renderer/src/store/editor.ts`、`pages/app.vue`
- `packages/desktop/src/renderer/src/assets/window-controls.ts`
- `packages/desktop/src/shared/types/ipc.ts`
- `packages/desktop/build/icons/icon.png`（MarkText 图标替换）

冲突解决原则：保留 `port/harmony` 侧的鸿蒙逻辑，合并上游的新功能代码。

## 其他注意事项

- `D:\Code\ArkTs\MarkText`（鸿蒙工程）本身**不跟踪**构建产物（web/assets、main.js 等），
  仅跟踪源码；产物每次由 `build.ps1` 重新生成。
- 鸿蒙工程的 ETS 侧适配（web_engine/electron 模块）与上游 MarkText 无关，不随上游更新。
- 构建脚本 `scripts\port\build.ps1` 是唯一入口，替代原先散落的命令行步骤。
