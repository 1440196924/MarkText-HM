# 碰一碰图片插入 Markdown 设计文档

## 1. 背景与目标

**场景**：在 2in1/PC 设备上用 MarkText 编辑 md 时，用户打开手机图库的照片，用手机顶部"碰一下"MarkText 编辑窗口，照片自动作为图片插入到当前光标所在位置（markdown 语法 `![](...)`）。

**目标**：基于 HarmonyOS「碰一碰文件分享」能力（华为分享 / Share Kit）实现手机 → MarkText 的单向图片传输与插入，复用现有渲染进程的图片插入机制。

## 2. 可行性结论

**可行**，依据：

- 官方提供 `@hms.collaboration.harmonyShare`（`SystemCapability.Collaboration.HarmonyShare`），其中 `on('dataReceive', { windowId, capabilities }, cb)` 是专门给 **PC/2in1 应用窗口**接收碰一碰文件的接口（其他设备类型返回 801）。
- 接收端可把文件收进**应用沙箱**（`receiveTarget.receive(context.filesDir)`），`onDataReceived` 回调里拿到 `record.uri`。
- 本工程 `web_engine` 模块已有同类适配先例：`ShareAdapter.ets`（分享面板）+ `ShareAdapterBind.ets`（JS↔ETS 绑定），架构可直接复用。
- 本机 SDK（6.1.1/API 24）的 d.ts **已含** `harmonyShare` 的 `dataReceive` 声明（since 6.0.0(20)），编译无需升级 SDK；真机为 MOR-W52（HarmonyOS 7.0.0 / API 26），满足运行要求。

**软性前提（需用户侧满足，代码无法兜底）**：

| 前提 | 说明 |
|---|---|
| 同一华为账号 | 手机与 PC/2in1 碰一碰必须登录同一华为账号 |
| 双端亮屏且解锁 | 相碰时两端须亮屏解锁 |
| 华为分享服务开启 | 系统默认开启 |
| 设备类型 | PC/2in1（dataReceive 仅此形态可用） |
| 手机需支持碰一碰 | HarmonyOS 5 及以上手机 |

## 3. 总体架构与数据流

```
手机图库(照片) → 手机顶部碰 MarkText 编辑窗口
        │  (华为分享/NearLink 传输)
        ▼
ETS 侧 HarmonyShareAdapter                    (web_engine 模块)
  harmonyShare.on('dataReceive', {windowId, capabilities:[IMAGE]}, cb)
  cb → receiveTarget.receive(context.filesDir, { onDataReceived })
  onDataReceived → 得到 record.uri (沙箱内 file:// URI)
        │  通过 bind 时的 JS 回调回调 (payload: string)
        ▼
JS 主进程 main.js / editor.ts
  回调里 webContents.send('mt::knock-image-received', { path })
        │
        ▼
渲染进程 editor.vue
  监听 'mt::knock-image-received'
  → 复用现有 editor.insertImage({ src }) → 光标处插入 ![](path)
```

## 4. 模块改动清单

### 4.1 ETS 侧（web_engine 模块）

**新增 `web_engine/src/main/ets/adapter/HarmonyShareAdapter.ets`**

- 依赖注入：`ContextAdapter`（拿 UIAbilityContext）、`AbilityManager`（拿 window）。
- 方法：`registerDataReceive(windowId: number, callback: (uri: string) => void)`。
  - `harmonyShare.on('dataReceive', { windowId, capabilities: [{ utd: 'general.image', maxSupportedCount: 1 }] }, (receiveTarget) => { ... })`
  - 回调内 `receiveTarget.receive(fileUri.getUriFromPath(context.filesDir), { onDataReceived: (data) => { const uri = data.getRecords()[0].uri; callback(uri) }, onResult: (code) => {...} })`
- 方法：`unregisterDataReceive(windowId: number)` —— 窗口销毁时调用 `harmonyShare.off(...)`，避免泄漏。
- 能力检查：注册前 `canIUse('SystemCapability.Collaboration.HarmonyShare')`，不满足则直接返回失败。

**新增 `web_engine/src/main/ets/jsbindings/HarmonyShareAdapterBind.ets`**

```ts
JsBindingUtils.bindFunction('HarmonyShare.RegisterDataReceive', registerDataReceive);
JsBindingUtils.bindFunction('HarmonyShare.UnregisterDataReceive', unregisterDataReceive);
```

- 注册进 `JsBindingMethod.ets` 的 `bind()`。
- 新增 `AdapterModule.ets` 的 `bind(HarmonyShareAdapter).toSelf()`。

### 4.2 JS 主进程（marktext 工程 `packages/desktop/src/main`）

- 在编辑窗口 `webContents` 就绪后（editor.ts 现有 OnContentReady 附近），调用：
  ```ts
  systemPreferences.callArkTSFunction('HarmonyShare.RegisterDataReceive', 'void', [windowId, callback])
  ```
  - `windowId`：系统窗口 ID。编辑窗口创建时用 `AppWindow.GetWindowId(id)`（`AppWindowAdapter.ets:806` 已实现）从内部 id 换算，或 ETS 侧用 `window.getLastWindow(context)` 获取。
  - `callback`：`(uri: string) => void`，收到图片 URI 后 `webContents.send('mt::knock-image-received', { path: uri })` 发给**对应**编辑窗口。
- 窗口关闭时调 `UnregisterDataReceive`。
- **回调限制**：AKI 桥回调参数 ≤ 3 个、payload 仅支持基础类型（string 可以），所以图片信息必须用 `string` 传（URI 本身即是 string，天然满足）。

### 4.3 渲染进程（marktext 工程 renderer）

- `editor.vue`：新增 `ipcRenderer.on('mt::knock-image-received', ...)`，收到后调用现有 `insertImage(src)`（`editor.vue:1120`，其通过 `bus.emit`/`editor.insertImage` 在光标处插入）。
- 插入的 `src` 直接用收到的沙箱 `file://` URI。

## 5. 关键技术点与风险

| # | 风险/要点 | 影响 | 对策 |
|---|---|---|---|
| 1 | 沙箱 `file:///data/storage/...` 图片路径，渲染进程 web 页面能否加载预览 | 插入不生效/图片裂 | 先在真实环境验证；若 web 引擎不允许 file 访问沙箱，改为主进程读文件转 data URL 传给渲染进程，或复制到 md 同目录 |
| 2 | `receiveTarget.getInfo()`（碰触点屏幕坐标）仅在 API 26 提供，当前 SDK 24 的 d.ts **无声明**，ArkTS 编译不过 | 无法精确插到碰触点 | MVP：**插入当前光标位置**（满足"插入当前 md"）；精确插入列为后续增强（需升级 SDK/绕开类型检查） |
| 3 | AKI 回调 payload 仅基础类型 | 复杂对象传不过去 | 只传 string（URI） |
| 4 | `dataReceive` 仅 2in1 有效，其他形态返回 801 | 真机验证受限 | 真机为 MOR-W52(2in1)，满足 |
| 5 | 华为分享会话并发/去重 | 连续碰多次 | 每次 onDataReceived 独立处理；文件重名加时间戳前缀 |
| 6 | 沙箱文件会累积 | 占空间 | 收图目录按天/月清理（后续增强） |
| 7 | 注册需正确 windowId，设置窗口不注册 | 碰设置窗口无反应 | 只对编辑窗口注册；同一时刻只保留一个监听 |

## 6. 分阶段实施计划

**Phase 1（MVP，本次实施）**
1. `HarmonyShareAdapter` + Bind + 注册进 AdapterModule/JsBindingMethod。
2. JS 主进程注册监听、转发 IPC。
3. 渲染进程接收并 `insertImage`。
4. 真机验证：手机图库照片碰编辑窗口 → 当前光标处出现 `![](file:///data/storage/...png)` 且可预览。

**Phase 2（增强，视结果）**
- 碰触点坐标精确定位（`getInfo()`，需 SDK 26）。
- 收图复制到 md 相对目录（对齐 `imageInsertAction` 设置项）。
- 沙箱清理、多图连传（maxSupportedCount > 1）。
